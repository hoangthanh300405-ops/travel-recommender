# Travel Destination Suggestions & Itinerary Planner

A hybrid recommender system that suggests travel categories to users based on
past ratings, built as an end-to-end ML engineering portfolio project — data
cleaning, hybrid recommender design, leakage-free evaluation, cold-start
handling, and (in progress) a bridge to real Vietnamese travel data.

## Results

| Model | RMSE (test) | MAE (test) |
|---|---|---|
| CF-only (SVD) | 1.1080 | 0.7902 |
| **Hybrid (CF + content)** | **1.1063** | **0.7855** |

| Ranking @5 | Precision | Recall | Coverage |
|---|---|---|---|
| **Hybrid** | **0.258** | **0.918** | 100% |
| Popularity baseline | 0.238 | 0.841 | 100% |
| Random baseline | 0.176 | 0.626 | 100% |

**Cold-start simulation** (150 users fully excluded from CF training, to
simulate genuinely new users): Hybrid RMSE = 1.213 vs. CF-only RMSE = 1.334 —
a **9.1% improvement**, showing the content component's real value for users
the collaborative signal can't reach.

Full breakdown (candidate-pool sizes, threshold sensitivity) in
[`artifacts/metrics.txt`](artifacts/metrics.txt).

## Known limitations (read before asking "why is recall so high?")

- The catalog is only **24 categories**, and the rating matrix is ~96% dense
  (68% of users have rated all 24). Candidate pools per user in the ranking
  eval average **~8.6 items** for K=5 — a much easier task than ranking among
  hundreds/thousands of unrated real-world places. Recall@5 should be read
  with that in mind, not as evidence of large-catalog ranking skill.
- The source dataset (see below) has category-level average ratings only, not
  per-place ratings — a real "recommend me *this specific museum*" system
  needs a place-level dataset (see Roadmap).
- Cold-start weight for brand-new users (`WEIGHT_CF_NEW_USER = 0.4` in
  `src/03_journal_to_wide.py`) comes from a **simulated** cold-start
  experiment (held-out UCI users), not real journal data yet.

## Architecture

```
google_review_ratings.csv (raw)
        │
        ▼
  load_and_clean_data()      ← fix out-of-range/zero cells, log every change
        │
        ▼
  train/val/test split (70/10/20, seeded)
        │
        ├──► SVD collaborative filtering  (scikit-surprise, 2-stage grid search)
        │
        └──► item-item content similarity (Pearson, train split only)
                        │
                        ▼
              hybrid_score() = w·CF + (1-w)·content
                        │
                        ▼
        evaluated vs. popularity & random baselines
        + cold-start simulation + threshold sensitivity
```

Extension pipeline (in progress, not yet run on real data):

```
Google Local Review metadata (US) ──► 02_category_crosswalk.py ──► category_crosswalk.csv
                                                                          │
journal_log.csv (real user entries) ──► 03_journal_to_wide.py ◄─────────┘
                                                │
                                    df_wide_journal (same shape as UCI matrix)
                                                │
                              reuses cf_model / item_similarity from src/train_hybrid_recommender_v3.py
```

## Setup & running

```bash
pip install -r requirements.txt
```

1. Download `google_review_ratings.csv` (UCI Travel Review Ratings, see
   Dataset below) and place it in the repo root (or wherever you point
   `DATA_PATH` in the script).
2. `python src/train_hybrid_recommender_v3.py` — runs the full pipeline:
   cleaning → CF + content training → hybrid tuning → ranking eval vs.
   baselines → cold-start simulation → threshold sensitivity. Writes
   artifacts to `artifacts/`.
3. (Optional, extension) `python src/02_category_crosswalk.py` — needs a
   manually downloaded `meta-<State>.json.gz` from the Google Local Review
   dataset (path configured at the top of the file).
4. (Optional, extension) `python src/03_journal_to_wide.py` — needs a real
   `journal_log.csv` (see `templates/journal_log_template.csv` +
   `docs/journal_schema.md` for the expected format).

## Dataset

[UCI Travel Review Ratings](https://archive.ics.uci.edu/dataset/484/travel+review+ratings)
(Renjith, S. et al., 2018) — 5,456 users × 24 travel categories, Google review
average ratings on a 1–5 scale. License: CC BY 4.0.

> Renjith, S. (2018). Travel Review Ratings. UCI Machine Learning Repository.
